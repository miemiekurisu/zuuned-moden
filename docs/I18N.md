# Interface language: wording is a file

Zuuned's interface text is data. The Chinese is written in
`i18n/zh_CN.tsv`, becomes a Qt translation source, and is loaded by a running
Zuuned at start. Changing a sentence on screen is an edit to that one file and a
restart; it does not need a compiler. A sentence typed straight into a QML
property or a C++ literal cannot be translated at all, so this repository treats
one as a defect whether or not anyone currently wants a second language, and
`python i18n/audit.py` fails the tree when it finds one.

## The pipeline

    i18n/zh_CN.tsv          the language file. One message per line:
                            source ~=> Chinese
                            UTF-8 without BOM, LF, literal backslash-n for a
                            newline inside a message.
              | i18n/update.ps1   lupdate over the listed sources; refreshes
              v                   <source> and keeps matched <translation>
    i18n/zuuned_zh_CN.ts    the translation source. Checked in.
              | i18n/fill.py      writes the tsv Chinese back over the .ts, so
              v                   rewording never means re-translating by hand
    i18n/build/zuuned_zh_CN.qm    lrelease output. Not checked in.
              |
              +-- CMake compiles the .ts into :/i18n inside the executable
              +-- i18n/build_qm.ps1 -NextToExe also drops the .qm in
                  build/i18n/, which a running Zuuned prefers

The reword loop, when the executable already exists, is the short one:

    edit i18n\zh_CN.tsv
    pwsh -NoProfile -ExecutionPolicy Bypass -File i18nuild_qm.ps1 -Fill -NextToExe
    restart zuuned

`i18n/update.ps1` is only needed when the sources changed - a new page, a new
status line, a sentence whose wording was edited in code. lupdate keeps the
Chinese for any source it still recognises, so running it is cheap; a source that
moved text loses that message and `fill.py` reports it as MISSING.

## Choosing the language

Settings -> Appearance -> Language writes `uiLanguage` to the settings ini
(under `%APPDATA%/Zuuned` on Windows, `$HOME/.config/Zuuned.conf` on Linux)
says plainly that it needs a restart. `installUiLanguage()` in `src/main.cpp`
takes the decision once, before the QML engine exists, because a QTranslator
installed later repaints nothing. `system` resolves Chinese when the OS locale is
Chinese and English otherwise, and does so silently; only a language the build
cannot honour says so on the log. The session log line names what actually
happened, and the Language card reports the applied language next to the request:

    [i18n] UI language zh_CN; catalogue D:\workspace\...\build\i18n; Qt catalogues: qtbase, qtquickcontrols2

`ZUUNED_I18N_DIR` overrides where the external catalogue is looked for, which is
what a packaged layout or a test harness uses.

| QML files in `update.ps1` | 57 |
| C++ files in `update.ps1` | 21 |

`i18n/update.ps1`'s source list *is* the coverage claim. A page that is not in it
is not translated, whatever it looks like, and a page in it without a shipped
translation is a page that lies about being Chinese.

## When one English word is two words in Chinese

A tsv line is either

    source ~=> Chinese

or

    Context!source ~=> Chinese

The second form exists because one English label can mean two things. `Albums` is
专辑 beside Artists and Songs, and 相册 beside photo Folders; a single bare line
would have to be wrong in one of the three places it appears (`MusicPage`,
`LibraryPhotosView`, `DevicePicturesPage`). The prefix is the lupdate `<context>`
name, which for QML is the file's base name.

`i18n/fill.py` reads a scoped line only when the head names a `<context>` that
really exists in the `.ts`, so wording that legitimately contains `!` still
resolves as itself; and a scoped line wins over a bare line for that context,
while every other context keeps falling back to the bare line. Which means a word
that needs a scope must never get a bare line of its own: `Albums` has three
scoped lines and no bare one, so a fourth `Albums` appearing in a new file shows
up as MISSING instead of silently inheriting 专辑. `python i18n/audit.py` counts
the scoped lines on its `tsv:` row and reports a missing pair as
`MISSING: MusicPage!Albums`, never as a bare source.

## Two kinds of string, and only one is wording

A label the user reads is wording. An identity token is not.

Wording goes through the catalogue: every `text:`, `title:`, `placeholderText:`
and `toolTip:` in QML uses `qsTr()`, and every sentence C++ hands to the interface
goes through `UiText::tr()` (`src/UiText.h`), which lupdate extracts under the
fixed context `UiText` and `QCoreApplication::translate("UiText", ...)` looks up
the same way. Extraction and lookup agree by construction; rename the struct
without renaming the context and those strings fall back to English on their own.

Never translated, on purpose:

- tokens compared as values, not shown as text: `"Unknown Artist"`,
  `"Unknown Album"`, `"Unknown Genre"`, `"Various Artists"`, `"Cancelled"`, a
  QML `root.pivot === "Albums"` key, the strings `NetworkAccess` writes into the
  session log and asserts on in `librarytool`;
- proper names and the language picker's endonyms (`English`, `中文`), Zune model
  names, font families, unit fragments, and a date format such as
  `d MMM HH:mm`.

Fragmenting a sentence to translate a word is worse than English. Every `%1` is a
whole message; where a literal used to be spliced together at runtime
(`qsTr("a") + name + qsTr("b")`) the fragments were folded into one message with
numbered placeholders, because a language cannot reassemble English word order.
A plural suffix that arrives as an argument (`"%1 %2s"`, where `%3` is a literal
`"s"`) is simply not carried into Chinese - an unused placeholder is harmless, a
stray latin `s` in a Chinese sentence is not.

## The audit

    python i18n/audit.py            four checks, exit 1 on a failure
    python i18n/audit.py --list     print the source line beside each finding

- `catalogue`: every source lupdate found has Chinese. An unfinished entry
  renders as English, which is the bug.
- `tsv`: the file is well formed, every line names a source that still exists
  (a stale line is a warning), and nothing is missing.
- `qml`: a quoted literal on a user-facing property sits inside `qsTr()`, over both
  `qml/*.qml` and `qml/*.js` - a label assembled in a JS table reaches a `text:`
  property just as easily.
- `cxx`: a sentence-shaped literal under `src/` or `transcode/` sits inside
  `UiText::tr()` / `tr()`, or is named in `i18n/audit-allow.txt` with a reason.

Both text checks are shape heuristics and say so; the allow file is the review
surface and is short enough to read. Three rules in `audit.py` exist because
reading one line at a time is not enough:

- a `text:` binding is followed across lines until its brackets close, so a
  `qsTr(...)` split over four lines is seen;
- a continuation line that starts with an operator, a ternary branch or a quote
  carries the binding too - kept deliberately tight, because a looser carry
  swallowed `FontMetrics {` and reported 103 phantom findings;
- a literal that is an operand of `=== | !== | == | !=` is blanked before the
  check, because it is a token.

A finding reports the line where the binding starts, not where the literal sits.

`audit-allow.txt` holds three kinds of rule - a literal pattern, a whole file
(`SKIP-FILE`, with a reason; `src/library/NetworkAccess.h` is the one there), and
a single line (`SKIP-LINE`). Keys are whitespace-stripped, so an entry written
`MB` also matches `" MB"`.

## Windows notes

`lupdate`/`lrelease` come from the same Qt as the build
(`D:\dev\Qt\6.11.0\msvc2022_64\bin`). `lupdate` prints
`Class 'UiText' lacks Q_OBJECT macro` on every run; that is the sound of the
header-only door working, not a warning to fix. The tsv stays UTF-8 without BOM
and is read as bytes-decoded UTF-8 everywhere, so this GBK machine cannot touch
it; a QML file's text reaches the catalogue as UTF-16 through Qt and never as a
local 8-bit path, so none of the `QFile::encodeName()` rules in
`docs/WINDOWS_COMPAT_AUDIT.md` apply here.

QML is embedded in the executable, so a QML wording change needs a relink to show
up in the *compiled-in* copy - but the external `build/i18n/zuuned_zh_CN.qm` is
read first, which is why the reword loop above restarts instead of building.
